# Contributing to OpenSpace

Thank you for helping improve OpenSpace.

1. Search existing issues and changes before starting substantial work.
2. Discuss architectural or user-visible changes in an issue and document the intended behavior and verification.
3. Create a focused branch and preserve unrelated work.
4. Add tests for behavior and failure paths. Run `corepack pnpm verify` before opening a pull request.
5. Update operator, security, compatibility, or migration documentation when the change affects it.
6. Complete the pull-request checklist. Keep commits reviewable and never commit credentials, production data, generated secrets, or private reports.

Contributions are licensed under the repository license. By submitting a contribution, you certify that you have the right to do so under the [Developer Certificate of Origin](https://developercertificate.org/); add `Signed-off-by: Name <email>` to commits.

Security vulnerabilities must follow [SECURITY.md](SECURITY.md), not the public issue tracker. Community support is best-effort; see [SUPPORT.md](SUPPORT.md).
