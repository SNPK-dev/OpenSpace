# Личный сервер OpenSpace: состояние и схема подключения

Этот документ описывает **текущий предварительный стенд**, а не обещание готового установщика. Сейчас сервер OpenSpace состоит из API, Web, realtime gateway, PostgreSQL, Redis, MinIO, LiveKit, Coturn и Caddy. На Mac и Windows для его запуска нужен Docker Desktop; «скачал один файл и запустил без зависимостей» пока не реализовано. Не распространяйте LAN test bundle как стабильный релиз.

## Адрес сервера

OpenSpace использует два имени: адрес приложения (`PUBLIC_BASE_URL`) и адрес вложений (`OBJECT_STORAGE_PUBLIC_ENDPOINT`). Клиентам должны быть доступны **оба**. Для звонков также нужны адрес LiveKit и медиапорты. Один IP в поле «Добавить сервер» не подменяет адреса вложений и медиа, заданные сервером.

Запись в `hosts` лишь сопоставляет имя с IP **на одном устройстве**. Она не создаёт сеть, не шифрует соединение и не делает сертификат доверенным. Для нескольких друзей придётся настраивать каждый клиент, поэтому это допустимо только для контролируемого локального теста. Отключать проверку сертификатов ради обычного пользователя нельзя.

Практические варианты:

1. **Домашняя сеть, временный тест.** Дайте хосту постоянный LAN-адрес, настройте локальные DNS-записи для имени приложения и файлов на каждом клиенте (или временно `hosts`), установите локальный корневой сертификат Caddy в доверенные на каждом устройстве. Откройте нужные TCP/UDP порты в firewall. Сертификат и DNS должны соответствовать одним и тем же именам. Текущий Windows LAN launcher автоматически делает это только для собственного тестового браузера и использует `--ignore-certificate-errors`; это не инструкция для друзей.
2. **Друзья через интернет, закрытая группа.** Tailscale может заменить Hamachi как приватная сеть: хост [делится конкретным устройством](https://tailscale.com/kb/1084/sharing) с приглашёнными пользователями; на каждом клиенте нужен Tailscale. [MagicDNS/HTTPS](https://tailscale.com/docs/how-to/set-up-https-certificates) помогает дать доверенное имя для веб-входа. Отдельно надо обеспечить второе имя для MinIO и доступ к UDP-медиа/relay, проверить ACL и firewall. [Tailscale Serve](https://tailscale.com/docs/reference/examples/serve) для одного веб-порта **не покрывает автоматически** MinIO и WebRTC. Эта конфигурация пока не принята end-to-end как установщик OpenSpace.
3. **Публичный сервер.** Рекомендуемый нынешним проектом путь: два публичных DNS-имени и действительные TLS-сертификаты Caddy, с настроенными LiveKit/Coturn и открытыми медиа-портами. См. [domain-tls-turn.md](../runbooks/domain-tls-turn.md).

При вводе IP клиент показывает предупреждение и всё равно требует обычной проверки TLS. Голый IP без `https://` нормализуется в `https://IP`; это **не гарантия**, что у сервера есть подходящий сертификат. Для HTTP вне localhost клиент показывает отдельное предупреждение; веб-камера, микрофон и показ экрана требуют доверенного secure context. В личной установке используйте HTTPS с проверенным сертификатом и не передавайте друзьям флаг обхода сертификата.

## Проверка на каждом хосте

| Хост | Фактически проверено | Пока не подтверждено |
|---|---|---|
| Mac | Отдельный Docker QA stack поднимался; веб-клиент и macOS App участвовали в двухмашинной матрице | Скачиваемый серверный установщик, доверенный LAN/Tailscale HTTPS для друзей, OS-level screen capture |
| Windows | Отдельный Docker QA stack поднимался; Windows Web/App участвовали в двухмашинной матрице | Скачиваемый серверный установщик, доверенный LAN/Tailscale HTTPS для друзей, полная стабильность межмашинного screen stream |

QA stack использует тестовые профили и локальную прокладку SSH для Web/API. Его успех **не доказывает** сценарий «друг скачал клиент, ввёл адрес и подключился без настройки».

## Приёмка личного сервера

Для каждого из двух хостов проведите одинаковый опыт с чистого клиентского устройства без SSH-туннеля и без `--ignore-certificate-errors`:

1. Установите и запустите сервер по пользовательской инструкции; запишите затраченное время, ручные шаги и ошибки первого запуска.
2. Скопируйте показанный сервером адрес в чистый Web и desktop-клиент. Проверьте сертификат приложения и адреса файлов; создайте двух разных пользователей.
3. Передайте сообщения и файлы в обе стороны. Проверьте скачанный файл по SHA-256, размеры 0, 1, 50 и 50+ МБ, отмену, повтор и ошибки сети.
4. Проведите голосовой и видеозвонок, показ экрана с движущимся изображением не менее 10 минут; сохраните RTP-статистику, записи и лог перезапуска/переподключения.
5. Остановите и снова запустите сервер, убедитесь, что данные и доступ пользователей сохранены. Повторите после перезагрузки хоста.

Пока все пять пунктов не пройдены для обоих хостов с обычными установочными файлами, личный сервер следует считать **не готовым к выпуску**.

Текущая граница вложений — 50 МиБ. Клиент отклоняет больший файл, API отклоняет заявленный размер и при подтверждении сверяет реальный размер объекта с заявленным. Однако временная подписанная ссылка MinIO сама по себе не ограничивает количество переданных байтов до подтверждения. Защита хранилища от намеренной загрузки чрезмерного объёма остаётся отдельной задачей перед публичным доступом.
