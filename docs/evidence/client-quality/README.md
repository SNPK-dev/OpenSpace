# Client quality release evidence

This directory documents the evidence contract. RC evidence is stored off-repository, downloaded over HTTPS by the protected release workflow, verified against configured SHA-256 values, and retained as a release artifact. This avoids a self-referential commit where adding an evidence file would change the `release_sha` it attests. The two records are named `usability-session.json` and `nvda-smoke.json`. Windows cold-start and memory evidence is generated by CI and retained as a release artifact.

Each record must contain:

```json
{
  "schema_version": 1,
  "completed_at": "2026-08-11T00:00:00Z",
  "release_sha": "40-character Git commit SHA exercised by the participants",
  "environment": "Exact browser, Windows, hardware, or assistive technology versions",
  "participants": [{ "anonymous_id": "participant-1", "consent": true }],
  "journeys": ["Canonical journey identifiers listed below"],
  "blocking_findings": 0,
  "result": "pass"
}
```

`usability-session.json` requires at least two distinct consenting participants and every journey: `invite-to-first-message`, `second-device-pair-and-revoke`, `offline-send-and-retry`, `upload-failure-cancel-and-retry`, `voice-reconnect`, `lost-device-recovery`, and `operator-backup-upgrade-failure-recovery`.

`nvda-smoke.json` requires at least one consenting participant and `onboarding`, `messaging`, `pairing`, `file-upload`, and `voice`. In release CI, `release_sha` must exactly equal the commit being released.

Do not add placeholder pass records or commit participant records to the repository. Human-session records require participant consent and must not contain names, credentials, message content, or recordings. Performance evidence must contain the raw measurements and budget comparison in additional fields.
